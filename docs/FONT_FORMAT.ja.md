# TinyFont — フォント形式

内部の記録。日本語のみ。**形式の定義と、そう決めた実測。**

TinyGFX はフォントデータを 1 つも同梱しない（[DECISIONS.ja.md](DECISIONS.ja.md) D17）。
ここで決めるのは**受け取る形**だけ。生成は [LGFXFontToolJs](https://www.npmjs.com/package/lgfx-font-tool) が行う。

## 1. 中心の考え方

> **選択は実行時ではなく生成時に済ませ、結果をデータで表す。**

決めることは 2 つだけ。どちらも**ポインタが `nullptr` かどうか**で表す。

| 選択 | `nullptr` のとき | 非 `nullptr` のとき |
| --- | --- | --- |
| `codes`（索引） | **連続** — `first` から `count` 個 | **疎** — 昇順のコード表を二分探索 |
| `glyphs`（グリフ表） | **固定ピッチ** — 全グリフ共通の幅・送り幅 | **可変ピッチ** — 4 バイト/字 |

4 通りの組み合わせすべてを 1 つのデコーダが扱う。分岐は各 1 か所で、
**両方に対応するコストは合計 76 バイト**（§4 の実測）。

## 2. 構造

```cpp
struct TinyGFXGlyph {   // 可変ピッチのときだけ。4 バイト固定
  uint8_t offsetLo, offsetHi;  // bitmap 先頭からのバイトオフセット
  uint8_t width;               // グリフの幅（画素）
  uint8_t xAdvance;            // 送り幅
};

struct TinyGFXFont {
  const uint8_t*      bitmap;
  const TinyGFXGlyph* glyphs;  // nullptr = 固定ピッチ
  const uint16_t*     codes;   // nullptr = 連続索引
  uint16_t first, count;
  uint8_t  width, height, xAdvance, yAdvance;  // 固定ピッチ用 / 全グリフ共通
  int8_t   xOffset, yOffset;                   // 全グリフ共通
  uint8_t  bytesPerGlyph;                      // 固定ピッチ用。実行時に除算しないため
};
```

ヘッダは **24 バイト**（RV32 / 32bit ポインタ）。

**高さ・xOffset・yOffset をグリフごとに持たない**のが GFXfont との一番の差。
`yOffset` が共通なので ascent が定数になり、`setFont()` で全グリフを走査する必要もない。

ビットマップは「**行を連結した MSB first のビット列、グリフ間はバイト境界揃え**」。
GFXfont と同じ並びなので、既存の Adafruit 資産はツール側で変換できる
（ビットマップはそのまま、メタデータだけ組み替える）。

固定ピッチのときグリフ n の先頭は `bitmap + n * bytesPerGlyph`。表を引かない。

## 3. データ量

グリフ 1 字のビットマップを b バイトとすると:

| 形式 | データ量 |
| --- | --- |
| GFXfont（参考） | 12 + n × (b + 7) |
| TinyFont 固定ピッチ・連続 | 24 + n × b |
| TinyFont 固定ピッチ・疎 | 24 + n × (b + 2) |
| TinyFont 可変ピッチ・連続 | 24 + n × (b + 4) |
| TinyFont 可変ピッチ・疎 | 24 + n × (b + 6) |

### ASCII 全部（n=95、5x7 なので b=5）

| 形式 | データ量 | GFXfont 比 |
| --- | --- | --- |
| GFXfont | 1,152 B | — |
| **固定ピッチ・連続** | **499 B** | **−653 B（−57%）** |
| 固定ピッチ・疎 | 689 B | −463 B |
| 可変ピッチ・連続 | 879 B | −273 B |

**ASCII の固定ピッチフォントでは、GFXfont のグリフ表がデータの 58% を占めていて、
しかも中身は全字同一。** ここを落とすのが一番効く。

### CJK のサブセット（n=500、16x16 なので b=32）

| 形式 | データ量 |
| --- | --- |
| **固定ピッチ・疎** | **17,024 B** |
| 可変ピッチ・疎 | 19,024 B |
| GFXfont | **不可能に近い** |

GFXfont は `first`〜`last` が連続でなければならない。U+4E00〜U+9FA5 に散った 500 字を
収めるには 20,902 件のグリフ表（**146 KB**）が要る。実際に使う 500 字ぶんは 1 KB。
**疎索引はここで桁違いに効く。**

## 4. 実測（CH32V003 / -Os / 32 グリフ 5x7）

`tests/constructs/d`（構成 C + 文字）で測った。データ量は算術で分かるので、
**コード量 = Δflash − Δデータ**。

| 構成 | flash | 文字機能ぶん | うちデータ | うちコード |
| --- | --- | --- | --- | --- |
| C（文字なし） | 10,776 | — | — | — |
| **d（固定ピッチ・連続）** | **11,620** | **+844** | 184 | **660** |
| d_rec（可変ピッチ） | 11,748 | +972 | 312 | 660 |
| d_sparse（固定・疎） | 11,684 | +908 | 248 | 660 |
| （旧）GFXfont | 11,856 | +1,080 | 396 | 684 |

**TinyFont は GFXfont より 236 バイト小さい。** データで −212、コードで −24。
4 通りを扱うようになったのにコードが減ったのは、`setFont()` の ascent 走査が
消えたのと、グリフ表が 7 → 4 バイトになったため。

### 分岐そのもののコスト

```sh
-DTINYGFX_FONT_SPARSE=0    # 疎索引を落とす
-DTINYGFX_FONT_RECORDS=0   # 可変ピッチを落とす
```

| 構成 | flash | 削減 |
| --- | --- | --- |
| 両方あり（既定） | 11,620 | — |
| 疎なし | 11,564 | **−56 B** |
| レコードなし | 11,596 | **−24 B** |
| 両方なし | 11,544 | −76 B |

**結論: 既定で両方入れておく。** 76 バイトは、ASCII で 653 バイト、CJK で 145 KB
という節約に対して誤差。スイッチは「どうしても」のときのためだけに残す。

> 別途の測定では疎索引のコードを +124 B としていた。こちらの実測は +56 B。
> 実装が違う（こちらは uint16 の表を二分探索するだけ）。**どちらにせよ結論は変わらない。**

## 5. 圧縮しない

u8g2 の RLE は 16px で 3%、8px で 13% しか縮まない。デコーダのバイト数に見合わない。
**決着済み**（[DECISIONS.ja.md](DECISIONS.ja.md) D17、別途の測定でも裏付けられた）。

将来どうしても必要になったら、**別ヘッダの第 2 デコーダ**として足せる形にはなっている
（`glyphs` / `codes` と同じく、データ側のフラグで表す余地がある）。

## 6. 採らなかったもの

| 案 | なぜ採らなかったか |
| --- | --- |
| **コードの再マップ**（連番へ振り直す） | 疎索引比で 9% しか縮まないうえ、**文字列リテラルがそのまま使えなくなる**。割に合わない |
| **グリフごとの bbox**（GFXfont 方式） | 可変ピッチのビットマップは縮むが、グリフ表が 4 → 7 バイトに増える。5x7 級では bbox の節約より表の増加が勝つ。大きな欧文フォントでは逆転しうるので、**必要になったら測って決める** |
| **32bit オフセット** | 16bit で 64KB。それを超えるフォントは V003 級には載らない。必要になったらフラグで足す |
| **GFXfont をそのまま食う** | 上の実測どおり ASCII で 653 B 損。**ツール側が変換できる**ので互換は失われない |

## 7. LGFXFontToolJs への依頼

[EXTERNAL_REQUESTS.ja.md](EXTERNAL_REQUESTS.ja.md) E4 にまとめてある。要点:

1. **TinyFont 形式のエンコーダ**（`encodeCSource({format: 'tinyfont'})` 相当）
2. **索引とグリフ表を自動で選ぶ**（連続に収まるなら連続、固定ピッチなら表を省く）。
   選んだ結果をヘッダのコメントに書いてくれると、利用者がデータ量を把握できる
3. **PROGMEM 属性**をビットマップ・グリフ表・コード表・`TinyGFXFont` の 4 つすべてに付ける
4. **決定的な出力**（同じ入力 → バイト一致）。CI で `git diff --exit-code` して守るため

## 8. つなぎの実装

`tools/gen_font.py` が測定用に 5x7（0x20-0x3F の 32 字）を 3 変種で吐く。

```sh
python3 tools/gen_font.py --mode fixed
python3 tools/gen_font.py --mode records --symbol ... --out ...
python3 tools/gen_font.py --mode fixed --sparse --symbol ... --out ...
```

**変種を変えても描画結果が 1 画素も変わらないこと**は `tests/text/` が検査している。
