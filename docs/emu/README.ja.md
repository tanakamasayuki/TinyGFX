# 組込み検証プラットフォーム — 文書の入口

内部の記録。日本語のみ。**まだ実装していない。設計の検討まで。**

**先にあるべき姿を決め、既存のものはそれに合わせて作り直す。** 既存には
ホストコアのフック・各テストの自前モデル・TinyM5Board のトレース・
I2CDeviceDB の現在の形も含む。どれも素材であって錨ではない。

方針は 2 つ。

- **いまの工数より今後の工数のほうが大きい。** 足すたびに壊れないことを、
  速さや互換より優先する
- **契約はフレームワークにも実行形態にも依存させない。** Arduino にもさせない。
  Arduino は「最初から同梱されている 1 ポート」であって、前提ではない

読む順は **CONCEPTS → 自分の役割の 1 冊**。規約と語彙は CONCEPTS が正で、
役割別の 3 冊はそれを実装の義務に翻訳したもの。食い違ったら CONCEPTS が勝つ。

**固有名は足場。** いまの分冊は TinyGFX・TinyM5Board・host-arduino-core・
I2CDeviceDB を説明の足場に使っているが、**Protocol の正式な定義に固有の
リポジトリ名は残さない**（どれも捨てて作り直される可能性がある —— 特に
I2CDeviceDB）。凍結（段階 1）のときに役割名（データ柱・Arduino ホスト実装・
利用者の例）へ置き換えて掃除する。それまでは分かりやすさを優先して残す。
