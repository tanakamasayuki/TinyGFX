# 利用者のルール — テストの書き方

内部の記録。日本語のみ。2026-09-03 改訂。概念は [CONCEPTS.ja.md](CONCEPTS.ja.md) が正。

## 1. 全体の形

テストは **3 つの顔**を持つ（アプリは無改造のまま）:

| 顔 | いつ | できること |
| --- | --- | --- |
| **setup 相当**（フック） | アプリの setup 前後 | tick 設定・デバイスの確保と仕込み・attach・進行役の登録・初期 dump |
| **進行役**（もう 1 本の loop） | **毎 tick**（①の位置。待ちの中でも回る） | 単発注入・const 検分・tick を数える |
| **golden 照合** | 走行後 | イベント列（タグで濾す）・PPM・dump |

実例は host-arduino-core 1.7.0 同梱の `tests/runtime/accept_emu_tick`。
仮想時計 + 進行役 + GPIO 注入のボタン + 同一周内の AT→OK 往復が、この形の
最小完全形として通っている。

```
アプリ:  Wire.requestFrom(0x34)
           → ①汎用拡張点 → ②中間層 → ③契約（記録 + 表引き）→ デバイス
進行役:  毎 tick 呼ばれ、注入（契約経由・イベントに写る）と const 検分
テスト:  attach・仕込みはハンドル直（走行前）。golden は行単位の diff
```

## 2. 進行役の書き方

- **待たない**（待ち API は禁止 —— 診断イベント + no-op）。「20ms 後」は
  20 tick 数える状態機械で書く
- 注入は**単発のみ**。未来の予定表は無い
- 同一 tick 内の連続注入（LOW→HIGH）で縁が立ち、ISR は進行役が返った直後に走る
- ボタンは**デバイスではなく GPIO 注入**（プルアップなら LOW → n tick → HIGH。
  押した判定はアプリのデバウンスの仕事で、そこが被験部）
- GPS のような周期はデバイスの**通知チャネル**を叩く（推奨周期はデバイスが
  データで公開。デバイスに直接メソッドを呼ばない —— ログに写らないため）
- 検分はハンドル直の const（無記録）。**証拠に残したい検分は契約経由の
  `dump`**（1 行文字列でイベントに写る）

## 3. 登録（attach / detach）

- 統一 API（v0 案 —— 凍結は命名後）: `attach_i2c(ctx, bus, addr, ops, dev)` /
  `attach_spi(ctx, bus, cs 線, 役割表, ops, dev)` / `attach_uart(ctx, port, …)` /
  `attach_pins(ctx, 線配列, n, …)` と `detach`
- **attach は束縛表を兼ねる**: デバイスの役割番号（0 始まり）↔ 世界の線は
  ここで対応づける（`attach_pins` の線配列は添字 = 役割番号）
- バスは宣言不要（番号は鍵。`Wire`=0/`Wire1`=1 は Arduino 中間層の規約）。
  一意なのは宛先で、占有済みへの attach は音を立てて失敗。同じ実体の複数宛先は可
- 上限は 2 段: 型幅（IF）と、ctx に渡す表の容量（実際）

## 4. 観測と golden

- リスナーは何個でも・読むだけ。**1 イベント 1 行**なので golden は行 diff
- 出どころタグ（アプリ／注入／デバイス）と文脈タグ（main／ISR）で濾す ——
  アプリ操作だけの golden、注入込みの完全トレース、の両方が同じ列から作れる
- 環境の能力（`caps`）を先に確かめ、足りなければ skip

## 5. やってはいけないこと

- 走行中にハンドル直で状態を変える（仕込みは走行前、走行中の変化は注入で）
- 進行役・ISR の中で待つ
- 線番号を可搬にしたい台本に書く（線直の注入はその板に束縛される。可搬にする
  ならチャネル名で）
