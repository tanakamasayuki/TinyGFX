# パネルが合わないときに、どこを変えるか

> English: [PANEL_TUNING.md](PANEL_TUNING.md)

**パネルはプリセットです。** カタログの 1 枚を選んで include すれば、たいていは
そのまま出ます（[GLOSSARY.ja.md](GLOSSARY.ja.md)）。

出ないときのための文書です。**症状から、変えるところが引けるようにしてあります。**

直しかたは 3 種類あります。

| | 手間 | 例 |
| --- | --- | --- |
| **実行時のメソッド** | 1 行、どこにでも | 反転・ミラー・色順・オフセット |
| **include を替える** | パネルを選び直す | COM ピン配置（`_SeqCom`） |
| **`#define`** | include の前に 1〜2 行 | COM ピン配置・プリチャージ・VCOMH |

**COM ピン配置とプリチャージ／VCOMH は実行時に変えられません。** ビルドし直しです。

## 使いかた

1. **まず動くところまで持っていく。** 何か出ているなら、下の表で症状を引く
2. **1 つずつ試す。** 直ったら、その値を持つカタログの別の 1 枚を探すか、
   自分の 1 枚を作る（§4）
3. **直った値を教えてください。** カタログに入れれば次の人が引かずに済みます

## 1. まず「何も出ない」とき

表を引く前に、こちらが先です。**設定の問題ではないことが多い**ので。

| 確かめること | どうやって |
| --- | --- |
| **バスを `begin()` したか** | TinyGFX は `SPI.begin()` も `Wire.begin()` も呼びません（[DECISIONS.ja.md](DECISIONS.ja.md) D24）。**あなたが呼ぶ必要があります** |
| **`begin()` が true を返したか** | `false` は「設定が使えない」の意味です。バッファが null、高さが 8 の倍数でない、寸法が 0 のどれか |
| **バッファの大きさ** | `static uint8_t fb[TinyGFXPanelSSD1306_128x64::kBufferBytes];` と書けば間違えません。手で計算すると、足りなくても `begin()` は通り、書き潰します |
| **モノクロパネルで `display()` を呼んだか** | ページ方式のパネルは**呼ぶまで 1 バイトも送りません**。描いただけでは出ません |
| **I2C アドレス** | 0x3C か 0x3D。モジュール裏の抵抗で決まっていることがあります |
| **配線** | ソフト SPI ならピン番号、I2C ならプルアップ |

## 2. 症状の表

**上から順に、目で判定しやすいものです。**

| 見えかた | 変えるところ | どう書くか |
| --- | --- | --- |
| **白黒が反転している** | 反転 | `panel.invertDisplay(false);` を `begin()` の**後**に |
| **赤と青が入れ替わっている**（カラー） | 色順 | `panel.setRgbOrder(false);` |
| **左右が鏡像**（カラー） | ミラー X | `panel.setMirror(false, false);` |
| **上下が逆さま** | ミラー Y / 走査方向 | カラー: `panel.setMirror(mx, !my);` |
| **横に数ピクセルずれ、端に縦縞のゴミ** | 列オフセット | `panel.setColumnOffset(2);`（モノクロ）／ `panel.setOffset(x, y);`（カラー） |
| **1 行おきの縞になる／上下半分が入れ替わる** | **COM ピン配置** | カタログの `_SeqCom` 付きを試す（§3） |
| **絵がガラスの上半分に潰れる** | 高さ | パネルの選び直し。多重比は高さから出ます |
| **回転 0 は合うが 2 と 3 がずれる** | GRAM 寸法 | `panel.setGramSize(240, 320);`（カラー） |
| **暗い／ちらつく** | プリチャージ・VCOMH | §4。**目では判定しづらい**ので最後に |

### 反転とミラーは `begin()` の後で

`invertDisplay` / `setSleep` / `displayOn` は**バスに直接コマンドを出します**。
`begin()` の前に呼んでも、バスがまだ立っていないか、`begin()` 自身の初期化列に
上書きされます。

`setOffset` / `setGramSize` / `setMirror` / `setRgbOrder` / `setColumnOffset` は
**いつ呼んでも構いません**（バスに触らないため）。順序も自由です。

## 3. COM ピン配置だけは推測できません

**カタログのプリセットが本当に運んでいる値は、実質これ 1 つです。**

ガラスの COM 線の並び方で、2 通りしかありません。

| 値 | 意味 | 症状 |
| --- | --- | --- |
| `0x12` | Alternative（交互）。**データシートのリセット値** | — |
| `0x02` | Sequential（順番） | 間違えると 1 行おきの縞、または上下半分が入れ替わる |

**高さからは決まりません。** 128x32 は Sequential ですが、同じ 32 行の 64x32 は
Alternative です。**だから TinyGFX は高さから推測しません**（以前は推測していて、
その 2 品種で間違っていました）。

128x64 は両方が流通しているので、カタログに 2 枚あります。

| | |
| --- | --- |
| `panels/SSD1306_128x64.h` | Alternative（多数派） |
| `panels/SSD1306_128x64_SeqCom.h` | Sequential |

**縞が出たらもう一方を試してください。** 2 択なので、当たるか外れるかです。

## 4. 自分のパネルを 1 枚作る

カタログに無いとき、または上の表で直した値を固定したいとき。

`src/TinyGFX/panels/` の 1 枚を写して、`tools/gen_panels.py` のカタログに足すのが
正式な手順です。**手で書いたヘッダは次の生成で消えます**（テストが検出します）。

```python
dict(driver="SSD1306", w=128, h=64, suffix="MyModule", com_pins=SEQUENTIAL,
     note="どこで買ったか、どう見分けるか"),
```

書ける項目は 4 つだけです。**それ以外は導出されるか、コントローラのリセット値**
だからです（[GLOSSARY.ja.md](GLOSSARY.ja.md) §4）。

| 項目 | 省略したときの値 |
| --- | --- |
| `com_pins` | `0x12`（データシートのリセット値） |
| `col0` | ガラスは RAM の中央にあるものとして計算 |
| `gram` / `offset`（カラー） | パネル寸法と同じ／`(0, 0)` |
| `suffix` | 無し |

### プリチャージと VCOMH を変えたいとき

**輝度やちらつきが気になる場合だけ**です。目では正解が分からないので、
プリセットには持たせていません。スケッチ側で `#define` します。

```cpp
#define TINYGFX_SSD1306_PRECHARGE 0xF1   // 既定はデータシートのリセット値 0x22
#define TINYGFX_SSD1306_VCOMH     0x40   // 既定はデータシートのリセット値 0x20
#include <TinyGFX/panels/SSD1306_128x64.h>
```

> **他ライブラリが送っている `0xF1` と `0x40` は、データシートに無い値です。**
> `0x40` は VCOMH の表（`00h` / `20h` / `30h`）に載っていません。1 つの
> ライブラリの調整値が各社に写っている状態なので、TinyGFX の既定は
> **リセット値**にしてあります。明るさが足りなければ上の 2 行で近づけられます。

## 5. 何が繋がっているか読み出す

**カラーパネルで、MISO が配線されている場合のみ。** コントローラの ID を読めます。

```cpp
uint8_t id[3];
panel.readId(id);   // ILI9341 系なら 00 93 41 のような値
```

全部 `00` か全部 `FF` なら、**データ線が戻ってきていません**。M5Stack Core の
ように SDO が SPI の MISO ピンに来ていないボードでは読めません
（[MANUAL_TEST.ja.md](MANUAL_TEST.ja.md)）。

**モノクロの I2C OLED は読めません。** 書き込み専用です。

**TinyGFX はこれでパネルを自動判別しません。** 読めるバスと読めるパネルの
組み合わせが限られるうえ、ボードが分かっている状態でコンパイルされるライブラリに
実行時の判別は要らないためです。**あくまで「何が繋がっているか分からない」ときの
診断用**です。
